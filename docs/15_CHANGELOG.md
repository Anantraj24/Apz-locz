# 15 — Changelog

## [Unreleased]
- Phase 7: Relock Timing implementation.
  - Implemented `LockStateManager` (`DefaultLockStateManager`) holding an in-memory `ConcurrentHashMap<String, Long>` mapping unlocked package names to `elapsedRealtime` timestamps with clock injection.
  - Implemented all 5 relock modes per `docs/02_SRS.md §4` and `FR-04`, `FR-14`: `IMMEDIATELY`, `AFTER_10S`, `AFTER_30S`, `AFTER_1MIN`, and `ON_PHONE_LOCK` with zero background polling, alarms, or Handler loops.
  - Implemented dynamic `ScreenOffReceiver` listening for `Intent.ACTION_SCREEN_OFF` inside `AppWatcherService` to immediately clear all runtime unlock timestamps on device lock or display sleep.
  - Enhanced `ForegroundAppFilter` with `isTransientOverlay` and `isAppExit` to prevent spurious relocks during soft keyboard (IME) entry or SystemUI volume adjustments, while reliably triggering exit relocks when navigating Home or switching apps.
  - Integrated `lockStateManager.recordUnlock(packageName)` into `LockActivity` on successful PIN, password, pattern, and biometric unlock.
  - Added One UI "Auto Relock Timing" radio option list to `SettingsScreen` with live DataStore persistence.
  - Added unit test suite `LockStateManagerTest` validating all 5 timing modes, boundary conditions, and screen-off resets.
- Phase 6: Biometric Unlock implementation.
  - Implemented `BiometricHelper` utilizing `androidx.biometric:biometric:1.1.0` with `BIOMETRIC_STRONG or BIOMETRIC_WEAK` supporting both fingerprint sensors and system face unlock (including Samsung Galaxy S25 FE).
  - Configured prompt with "Use credential" fallback and zero `DEVICE_CREDENTIAL` permission or storage of biometric data.
  - Updated `LockActivity` (inheriting `FragmentActivity`) to auto-trigger the biometric prompt upon launch when enabled.
  - Added biometric re-trigger action key to the PIN keypad and unlock button for password/pattern inputs.
  - Added Biometric Unlock toggle to `SettingsScreen` reflecting device hardware availability and enrollment status.
  - Added unit test suite `BiometricSettingsTest` testing setting persistence and status enum integrity.
- Phase 5: Lock Screen & Credential Entry implementation.
  - Implemented `LockActivity` with `excludeFromRecents="true"`, empty `taskAffinity=""`, `launchMode="singleTask"`, and `noHistory="true"`.
  - Added home-screen navigation on Back press to prevent bypassing locked apps.
  - Built credential input composables: `PinInput` (dots and keypad), `PasswordInput` (secure text field with show/hide toggle), and `PatternInput` (3x3 dot touch drag grid with normalized dot sequences).
  - Built `LockScreen` showing target app identity, error state with spring shake animation, and lockout timer countdown.
  - Wired `AppWatcherService` to launch `LockActivity` whenever a locked application transitions into foreground.
  - Built `SettingsScreen` and `CredentialSettingsScreen` allowing users to configure PIN, Password, or Pattern credentials, change credentials, remove credentials, and switch theme modes.
  - Added unit test suite `LockScreenLogicTest` verifying PIN, password, and pattern unlock flows, 5-wrong lockout behavior, and credential modification.
- Phase 4: App List & Lock Selection implementation.
  - Implemented `AppInfo`, `RawAppInfo`, and `AppScanner` abstraction with `PackageManagerAppScanner` querying launcher intents via Android 11+ `<queries>` (zero `QUERY_ALL_PACKAGES` permission).
  - Implemented lightweight in-memory `IconCache` using `LruCache` for asynchronous icon loading with fallback placeholders, strictly avoiding external image libraries (no Coil/Glide).
  - Implemented `InstalledAppsRepository` (`DefaultInstalledAppsRepository`) combining installed apps with live DataStore `lockedPackages` and `showSystemApps` preferences.
  - Implemented `AppsViewModel` with reactive unidirectional data flow handling search filtering, All/Locked tabs, counts, and toggle mutations.
  - Built `AppsScreen` featuring One UI collapsing header, rounded search pill, tab counters, include system apps toggle card, 48dp app squircle icon rows, `OneUiSwitch`, and empty/loading states.
  - Updated `AppWatcherService` to dynamically observe `lockedPackagesFlow` without service restart, reacting strictly to user-locked apps in the foreground.
  - Added unit test suite `InstalledAppsRepositoryTest` verifying default user app filtering, locked system app visibility, search and tab filtering, and lock toggles.
- Phase 3: Foreground App Detection implementation.
  - Implemented `AppWatcherService` (`AccessibilityService`) listening for `TYPE_WINDOW_STATE_CHANGED` events.
  - Added `ForegroundAppFilter` with 200ms debounce and filtering for own package, system UI, launchers, and IMEs.
  - Configured `accessibility_config.xml` requesting zero unnecessary capabilities (`canRetrieveWindowContent="false"`).
  - Added temporary Foreground App Detection status card in `MainActivity` with live service state and quick shortcut to accessibility settings.
  - Added unit test suite `ForegroundAppFilterTest` verifying package filtering and debounce mechanics.
- Phase 2: Credential & Storage Core implementation.
  - Implemented `SettingsRepository` with Jetpack DataStore Preferences and keys matching `docs/06`.
  - Implemented `CredentialValidator` verifying PIN (4–8 digits), password (4–32 chars), and pattern (min 4 dots).
  - Implemented `Pbkdf2Helper` (PBKDF2WithHmacSHA256, random salt) and `CryptoEngine` (AES-GCM encryption with Android Keystore key alias `apz_locz_cred_key`).
  - Implemented `CredentialManager` for setting, constant-time verification, changing, and removing credentials with zero plaintext persistence.
  - Implemented `LockoutManager` enforcing 5 wrong attempts → 30-second lockout timer with countdown and clock injection for testability.
  - Implemented manual dependency injection via `AppContainer` in `ApzLoczApp`.
  - Added unit test suites (`CredentialValidatorTest`, `CredentialManagerTest`, `LockoutManagerTest`) covering all validation, lockout, expiry, and credential lifecycle rules.
- Phase 1: Foundation & One UI Design System implementation.
  - Initialized Gradle Kotlin DSL project with Version Catalog (`gradle/libs.versions.toml`).
  - Added One UI design system tokens (colors, typography, shape, spacing, motion).
  - Built core components: `OneUiCard`, `OneUiGroupedList`, `OneUiSwitch`, `PillButton`, `CollapsingHeaderScaffold`, `StatusBadge`, `PinDots`, and `PinKey`.
  - Created temporary Design Gallery screen in `MainActivity` with live theme switching and interactive PIN keypad.
  - Added unit test suite `OneUiThemeTest` verifying tokens.
  - Configured GitHub Actions CI workflow in `.github/workflows/build.yml`.
  - Added MIT License and `.gitignore`.
- Documentation package created (supersedes earlier "OneLock" draft files).
